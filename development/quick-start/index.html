Quick start

  1. Initialize the child pipelines and shared Boutros Lab modules:

bash git submodule update --init --recursive

  1. Prepare the input CSV with either MS data files supported by the selected conversion algorithm or Bruker .d directories, a target-decoy FASTA, and the MSFragger JAR. For .d input, also provide the diaTracer JAR and MSFragger ext/bruker directory. If selecting ProtLoom, also prepare a ProtLoom project YAML with the same FASTA and accession markers as the run configuration.

  2. Copy config/template.config to a run-specific file. Set input_csv, decoy_database, msfragger_executable, output_dir, and dataset_id. For .d input, set diatracer_executable and bruker_lib_dir. Set validate_ProteomicPSM.protloom_project_yaml when using ProtLoom. Review the shared markers and the child-specific settings for your experiment. Keep the template's includeConfig lines and final methods.setup() call.

  3. Run with Nextflow 24.10.6 and its v1 syntax parser. Choose a work directory with enough space for the acquisitions, reconstructed mzML files, and child pipeline work:

bash export NXF_VER=24.10.6 export NXF_SYNTAX_PARSER=v1 export NXF_WORK=/scratch/$SLURM_JOB_ID/SpectroMesa-DIA-work nextflow run main.nf -c /path/to/run.config -profile pines,standard

The scratch path above is an example for a Slurm job; use another suitable work directory outside Slurm. Select pines for a 64 CPU, 500 GB node or boutroslab_aws for a 32 CPU, 128 GB node. Add standard or docker for Docker, apptainer for Apptainer, or singularity for Singularity, for example -profile pines,apptainer. The runtime profile configures the parent ProteoVault process and passes the matching child_profile to every child pipeline. standard uses Docker by default when no runtime profile is selected. Apptainer and Singularity pull the ProteoVault OCI image through their Nextflow settings. Nextflow's -c option adds the run configuration to the project's configuration; see the Nextflow configuration documentation.

Reusing Apptainer images across runs

For runs with -profile pines,apptainer, export the cache location before starting Nextflow. Child pipelines inherit it even though each has its own work directory. Choose a persistent directory you own that all workers can access. For example, if your home directory is shared across workers:

export NXF_APPTAINER_CACHEDIR="$HOME/.cache/nextflow/apptainer"
mkdir -p "$NXF_APPTAINER_CACHEDIR"
  • QC uses apptainer.ociAutoPull = false. Nextflow stores the converted image in NXF_APPTAINER_CACHEDIR so later runs can reuse it. Without a configured cache, QC uses its own child-work/apptainer/ directory.
  • Tasks with apptainer.ociAutoPull = true, including ProteoVault, use Apptainer’s own cache. It defaults to $HOME/.apptainer/cache. To relocate it, export APPTAINER_CACHEDIR with a separate, persistent directory owned by your account.

Resource profiles

Profile Node budget Parent launch processes Child allocations
pines 64 CPUs, 500 GB 2 CPUs, 4 GB per child launcher diaTracer 12 CPUs/64 GB; MSFragger search 8 CPUs/64 GB; iProphet 8 CPUs/32 GB; DIA-NN 16 CPUs/96 GB; QC DIA-NN report 2 CPUs/32 GB.
boutroslab_aws 32 CPUs, 128 GB 2 CPUs, 4 GB per child launcher diaTracer 12 CPUs/64 GB; MSFragger search 8 CPUs/64 GB; iProphet 8 CPUs/32 GB; DIA-NN 16 CPUs/96 GB; QC DIA-NN report 2 CPUs/16 GB.

Parent CSV, conversion and reconstruction manifests, QC manifest, and configuration tasks request 1 CPU and 2 GB in both profiles. ProteoVault requests up to 8 CPUs/64 GB on pines and 4 CPUs/32 GB on boutroslab_aws. Parent child-launch processes request 2 CPUs and 4 GB from config/resources.json. Each profile has its own file under config/resource_profiles, containing its budget and CPU requests for every child process. A process memory value is optional: omit it to leave that child's Nextflow memory directive unset. search_database_MSFragger is the exception because it uses task.memory to size the Java heap. The profile's max_memory remains required as a node budget. The parent passes process requests through each child's parameter JSON and a small resource override config, including conversion, reconstruction, and qc-ProteomicDIA. Existing child resource defaults remain in effect when neither profile is selected. A run config can set base_resource_update within a child namespace to replace that profile's process requests. These profiles describe node budgets; they do not select a Slurm partition or change the local executor.

For a profile outside the repository, copy pines.json or boutroslab_aws.json to a directory you control, rename it <name>.json, and edit its budget and allocations. Set these values in your run config:

params.compute_profile = 'my_cluster'
params.additional_resource_profile_dir = '/path/to/resource_profiles'

Run with -c /path/to/run.config; a matching Nextflow -profile entry is not required. additional_resource_profile_dir can contain multiple directories separated by the operating system's PATH separator (: on Linux/macOS). Lookup checks those directories from left to right, then the bundled config/resource_profiles directory. Missing directories or missing files in one location are skipped. Relative directories resolve from the launch directory. A profile file found earlier takes precedence over a file of the same name found later. To add a bundled profile, add its name to config/profiles.config and create config/resource_profiles/<name>.json. The shared parent process requests usually do not need to change.
